## 验收主线

## 验证要求

- 新增接口覆盖成功、错误输入、历史版本、过期版本及并发变更。
- 完成审核必须由服务端拦截未满足条件，不能仅依赖按钮禁用。
- 导出不得将全部建议稿误标为当前稿；旧核验不得用于新稿件。
- 浏览器验证新增入口、保存恢复及下载；沿用当前“退出工作台”返回主页行为。
- 既有测试失效要区分旧界面定位与实际功能回归，不能直接删除业务断言。

## 修复后的使用方式

1. 在左侧“审查结论与执行记录”查看准入结论、覆盖范围和执行轨迹；在左侧准入结论与审查总评之间的“重点要求核验”查看核对结论；使用版本下拉框查看历史版本。
2. 右上角“导出”展开交付菜单，分别选择待审正文、当前采纳稿清洁版、当前采纳稿修订痕迹版、全部建议稿、全部意见书、已采纳意见书或 JSON 审核记录。
3. 在右侧“添加人工意见”填写风险；填写唯一匹配的原文和建议后可采纳替换，不填写原文的建议作为新增条款。
4. 重点要求核验仅展示核对情况，无需额外核验当前稿。
5. 全部条款意见处理完后点击“完成审核”，无需填写额外人工确认理由。
6. 点击“审查意见书”可预览、打印或下载Word；预览和Word从同一份报告内容生成。已完成任务重新打开仍可查看审查和意见处理记录。
7. “审查设置 → 修改审查条件”可维护背景、资料、制度要求，替换对比审查的参考合同；制度正文或要求改变后须重新确认。保存后旧审查结论保留，但不能用来完成新版本审核。
8. 审查执行期间可退出工作台或刷新；返回后点击“重新连接审查进度”，不会产生新的审查版本。停止任务请使用明确的取消按钮。

## 数据一致性约束

- 当前稿核验使用实际正文和审核要求摘要进行版本匹配，采纳组合改变导致正文变化时自动失效。
- 模型核验返回后再次检查任务输入和审查版本，防止核验期间的编辑被旧结果覆盖。
- 完成审核与人工确认留档在同一数据库事务提交；任务或审查记录发生并发变更时拒绝提交。
- 新增人工修订后，原全部建议稿核验被标为待确认；人工意见会进入处理进度、合同修订、意见书和审核记录。
- 浏览器断开仅停止订阅，不取消后台执行；主动取消会保留此前已完成的审查结果。
- 此实现仍面向单进程本机实例。服务重启会将执行中的任务标为中断，需重新审查；不承诺跨服务重启继续模型推理。
- 无可用模型时，要求核验保留“待确认”，不会伪造通过结论；人工确认保留独立理由，不更改机器核验原始结论。

### 业务分类与清单审查范围修复

- 清单模式改为全文风险审查 + 勾选清单专项核验，覆盖合规、权责平衡、财税结算与修订生成。
- 清单要求注入全文研判条件，独立保留逐项核验结果；意见统一归并，避免同一条款重复或冲突修订。
- 无可用模型时保留全文基础规则与清单匹配，明确提示未完成深度语义研判。
- 历史结果保持留档；原有任务需重新审查以生成完整结果。

### 统一重点要求与审查结果展示

- 自定义重点与清单要求可同时提交，不再因切换清单模式而清空自定义内容。
- 已确认制度要求、自定义要求、已选清单统一进入重点核验，并携带全部背景、资料和要求检查冲突；清单文字匹配不代替模型语义判断。
- 清单重点同步纳入建议稿与当前采纳稿要求核验，未满足项需按完成审核规则处理，不因退出专项分支而遗漏。
- 工作台、完成弹窗和意见书先展示重点要求结论，再展示全文分析；来源、证据、背景及参考资料可查看，旧版本与当前稿结论明确区分。
