# 审查闭环

本版本保持本机单人部署，不启用组织账号或审批流。

## 使用顺序

1. 上传合同或粘贴正文。默认通用中立立场，按需选择甲方／乙方和谈判尺度。
2. 在补充信息中填写交易背景、重点要求。重点要求每个非空行作为一项核验要求。
3. 上传 DOCX、TXT 或文字型 PDF 公司制度，选择“公司制度”，提取或手动录入要求。每项保留来源，可选择硬性要求或偏好；核对完整性后勾选确认。
4. 默认按计划执行。可选工具辅助核验，在本次合同和附件中进行最多三轮只读搜索、读取及结论验证。
5. 进入工作台核对合同后启动审核，查看准入、计划、处理进度及要求核验。
6. 在概览中核对原文与全部建议稿的要求覆盖情况。要求冲突时先修改条件、确认后重新审查；不会自动选定冲突要求的一方。
7. 逐项处理建议，下载 Word 当前稿／修订稿／意见书及 JSON 审核记录。审查记录页可查看统计和下载 CSV。

## 范围与限制

- 有可用模型时，准入检查以合同属性及请求用途分类；无效响应、异常或不确定结论停止本次审查，保留失败记录和此前结果。
- 无模型时仅作有限的合同要素识别，不声称已完成语义安全检查。明确显示安全待人工复核；快速规则结果也不等于完整法律审核。
- DOC 请先另存为 DOCX；扫描件须先 OCR；已有导入接口会拒绝空文件、损坏文件及无法提取文字的 PDF。
- 自定义要求和重点要求合计最多100项。参考资料最多5份、合计5万字；不会静默截断。
- 提取要求需要可用模型，必须引用制度中的实际原文；提取失败可手工整理。用户负责确认提取是否完整。
- 每批要求必须返回完整、唯一的ID集合；无法匹配的证据、缺少证据的通过结论或冲突项降为待确认。
- 全部建议稿核验基于所有建议组合，不等于部分采纳后的当前稿核验。修订建议变更后，原建议稿结论失效。单条AI重新生成会核验该条代入原文后的要求情况。
- 工具辅助核验只读本次输入，不提供联网法条检索或法规时效验证。未完成的判断保留待确认。
- JSON审核记录包含原始输入、快照、处理轨迹及人工处理状态；CSV每行代表一次审查尝试，不是一个合同。统计与导出默认覆盖全部记录，不受页面列表筛选影响。
- 输入和附件校验值用于版本比对，不是电子签名或防篡改审计服务。

## 实现位置

- `backend/review_policy.py`：准入、要求核验、执行计划及工具循环。
- `backend/workspace_review.py`：各审核方式的统一接入、建议稿核验。
- `backend/workspace_api.py`：要求提取、统计及记录导出。
- `tests/test_review_policy.py`：准入拒绝、来源证据、冲突、快照、报告及浏览器流程回归。
