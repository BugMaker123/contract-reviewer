# 后台审查与本地任务队列

## 使用方式

- 审查弹窗右上角可“最小化”，任务继续执行；右下角可恢复进度。最小化时完成会提示查看结果。
- 可以退出工作台，稍后从审查记录打开任务，再点击“查看后台进度”。这会订阅原任务，不会新建一轮审查。
- 排队任务显示位置，轮到后自动开始；可取消排队或取消执行。

## 调度规则

- 单进程内，同一实际 API Key 最多并发 5 个审查任务，包括准入、全文研判、要求核验和修订。
- Key 取值与模型客户端一致：优先请求配置，未提供时读取服务端 DEEPSEEK_API_KEY / OPENAI_API_KEY，去除首尾空白。
- 不同模型名称或端点使用相同 Key 时共享额度；不同 Key 独立调度。未配置 Key 的本地任务也有独立的 5 个并发额度。
- 每个 Key 使用 FIFO 队列，任务完成、失败或取消后推进后续任务；取消的等待任务不会进入执行。
- 排队时间不占用正式执行的 6 分钟超时。后台结果与任务输入仍在本机数据库中留档。
- API Key 不写入队列记录或数据库，调度分组只使用摘要；待执行任务配置仅保留在进程内存中。
- 本地内存队列不跨进程、不跨重启恢复。服务重启将执行中与排队中任务标记为中断，保留上一次已完成结果，用户可重新发起。

## 模块边界

- `backend/review_queue.py`：`ReviewQueue` 接口、`QueueTicket` 和 `LocalReviewQueue` 适配器。负责排队、准入与释放，不执行合同审查。
- `backend/review_jobs.py`：保留任务快照、等待准入、执行任务、广播 SSE、保存结果、取消及退出清理。
- `queue` SSE 事件：`status`、`position`、`limit`、`submitted_at`、`started_at`；不包含凭证或凭证摘要。
- `run.queue` 保存最近队列状态与时间，task/run 的 `queued` 状态支持记录查询。排队或执行中禁止改写输入、归档和重复发起。
- 旧同步与流式审查接口通过 `review_slot` 共享调度额度，避免绕过限制。

## 后续 Redis 适配

替换 `get_review_queue()` 工厂返回的适配器，保留 `enqueue / release / cancel` 与 Ticket 就绪信号、状态通知契约。Redis 适配需要实现跨进程原子并发额度、FIFO 消费、任务租约与故障回收，以及重启后可恢复的任务载荷；不能只把列表存入 Redis 就视为完成分布式调度。

## 验证

- 同 Key 5 并发、不同 Key 独立、环境配置与显式配置共用额度、不同端点同 Key 共用额度。
- FIFO、排队取消、执行取消、开始前取消、失败释放额度、重启中断标记与历史结果保留。
- 浏览器验证：排队、最小化、退出、从记录恢复、自动进入执行和后台完成，原任务只产生一轮审查。
