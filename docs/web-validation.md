# Web 化本地验证记录

验证日期：2026-10-26。环境：Windows、Python 3.14、MySQL 8.0.40。

## 已实施

- SQLAlchemy / PyMySQL 数据库边界，MySQL JSON 查询适配，版本化建表；保留 SQLite 作为本机与迁移源模式。
- 跨对象短写事务和 revision 冲突检查；同任务四个并发启动请求仅创建一个审查版本。
- Argon2 密码、服务端会话摘要、HttpOnly Cookie、CSRF、登录限流；首次/重置密码强制改密，改密、账号停用与角色调整撤销会话。
- 账号、角色、预置菜单操作权限，以及后端默认拒绝的 API 权限检查。个人业务与原件隔离，发布模板/清单按公共规则可用。
- 新建审查、起草需求的服务端工作副本；工作台与起草正文保存到服务端，Web 模式不从浏览器业务缓存或密钥恢复。失败保留输入并可重试。
- 管理员统一配置模型；密钥 Fernet 加密，API 不返回明文，调用端点仅允许服务器批准的 Origin。普通用户提交的模型密钥、端点不决定服务实际配置。
- 单进程审查排队、后台运行、重启中断；修复不同用户任务出队时持久化身份上下文串用的问题。
- 单独 Web 启动器、Nginx / systemd 样例、完整数据库与文件备份恢复工具。

## 本地数据

应用库 `contract_reviewer_web`，另建应用数据库账号，仅授权应用库。`.env.web` 与初始管理员信息均不入 Git。旧 SQLite、旧 sources 保留，迁移前快照在本机 artifacts 目录。

迁移：287 个业务对象、1,399 条审查事件、106 个原件；保留 ID、revision 与所有 kind。106 个文件的 SHA-256 全部匹配，无缺失、无未登记文件。原数据中 15 条模板发布/核验历史指向已删除模板，保持原快照与 parent，不虚构父记录，逐条列入迁移报告；个人旧记录统一归初始管理员。

完整备份恢复至独立 `contract_reviewer_restore_test` 库；校验全部 106 个文件，成功打开并导出一份历史已完成合同。报告与导出样本在 artifacts 内，本机演练不能替代机房异机备份。

## 测试

新增 MySQL、账号权限、草稿、模型加密、双用户排队和浏览器恢复测试 12 项通过。覆盖跨用户改 ID、source_id 引用、原件下载隔离、CSRF、重置/停用、revision 冲突、清浏览器缓存后恢复、MySQL 备份恢复后登录打开合同并导出。

定向业务回归：目录管理、起草、模板、核验记录、可靠性修复、排队、完成后导出，共 30 项通过（6 个浏览器用例未选入该轮）。前端生产构建通过。浏览器截图在 artifacts/web-draft-saved.png。

首次全量回归结果为 247 通过、45 失败。对导出策略、审查快照展示与字符比较等 15 个 API 失败，已在独立的未修改 HEAD 基线副本复现；原测试中还有依赖旧界面流程/选择器的浏览器失败，尚未逐条处理。本次不宣称存量全套测试通过。
